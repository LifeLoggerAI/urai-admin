## Status vocabulary

- **VERIFIED LIVE** — deployed and externally verified against the exact recorded SHA.
- **VERIFIED IN REPOSITORY** — implementation and repository tests are verified, but live parity is not claimed.
- **IMPLEMENTED BUT NOT DEPLOYED** — code is complete enough for release validation but no exact deployment receipt exists.
- **PARTIALLY IMPLEMENTED** — some source exists, but acceptance criteria are incomplete.
- **BLOCKED** — requires unavailable credentials, billing, external approval, device validation, or another unresolved dependency.
- **ROADMAP** — specified but not implemented.
- **REJECTED OR OBSOLETE** — removed from release scope or superseded by canonical ownership.

## Receipt rules

A receipt directory must be created under `docs/evidence/<release-or-work-item>/` or attached as a GitHub Actions artifact. Each receipt records repository, branch, commit SHA, changed files, PR/issue, test/build workflow, deployment target, deployed SHA, public URL, rollback SHA/release, and caveats.
