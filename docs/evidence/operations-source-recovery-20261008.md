# Source-bound Admin operations repair

This donor repairs the active operator scripts against the current canonical Admin app and Functions contracts. It is source preparation, not production, independent-review, monitoring or recovery acceptance.

- The rollback helper now rejects local/non-main execution, missing temporary WIF ADC, foreign projects, wrong current/rollback source and unbound/primary/sibling/multiple Hosting targets before provider execution. Hosting rollback reads back the approved known-good source rather than treating a successful CLI command as recovery.
- The public verifier uses `/api/health`, Functions `/health` and `/readiness`, parses their current JSON schemas, requires the exact approved app source version and the canonical Firebase project, and verifies anonymous redirects/401 responses. It does not accept a public `/admin` HTTP 200 or a health substring inside HTML. HTTPS requests have bounded connect/total timeouts and response bodies are not printed.
- The protected workflow builds the approved target version, rebuilds automatic rollback with the distinct approved rollback version, and verifies that version after recovery. Its receipt distinguishes public checks from separate authenticated RBAC, lifecycle, provider and recovery acceptance.
- The native CI includes actual-script synthetic execution tests. Adapters explicitly replace curl/Firebase/corepack, and the rollback workflow test uses a real isolated synthetic Git worktree. These do not call a provider, use genuine credentials, spend, restore data or certify live recovery.
